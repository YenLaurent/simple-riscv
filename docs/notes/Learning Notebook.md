## 7/29 RISC-V Instruction Set -- Basics

RISC-V有32个通用寄存器：`x0`到`x31`，每个寄存器定长：32位或64位，`x0`寄存器恒为0

要想选中32个通用寄存器，需要5位地址，因此在指令集中，所有的寄存器字段都是5-bit

在RISC-V中，内存存储的相邻指令的地址增量为4；内存存储的相邻数据地址增量也为4（均以字（32-bit）为指令/数据的计量单位，但地址是以字节为最小单位递增的）

因此，程序计数器PC每一次的增量均为4

### RV32I

- 汇编指令的操作数（rd、rs1、rs2）和机器指令（rs2、rs1、rd）是反序的
- RISC-V不管何种指令，立即数、源目标寄存器的相对位置都是一致的，例如，立即数总是在指令字段最高位，且立即数的符号位总是在`instr[31]`

#### R type

`funct7 (7bit) | rs2 (5bit) | rs1 (5bit) | funct3 (3bit) | rd (5bit) | op (7bit)`

R type的`op`操作码均为51，包括三个寄存器

#### I type

`imm (12bit) | rs1 (5bit) | funct3 (3bit) | rd (5bit) | op (7bit)`

包括一个立即数、两个寄存器，立即数替换R type中的源操作数

#### S/B type

`imm (7bit) | rs2 (5bit) | rs1 (5bit) | funct3 (3bit) | imm (5bit) | op (7bit)`

- S type中，`imm`12位作为完整的存储有符号立即数，`op`均为35
- B type中，有符号立即数为13位，表示分支偏移量，最低位恒为0；指令字段中只有高12位，且其立即数字段排布顺序为：`imm[12, 10:5]`和`imm[4:1, 11]`

#### U/J type

`imm (20bit) | rd (5bit) | op (7bit)`

与B type类似，J-type指令中剩余的20位立即数约定为21位跳转偏移量立即数的高20位有效位，立即数的最低有效位为0

U-type指令的20位立即数则只表示高20位，低12位恒为0

## 7/30 Program Counter

## 8/3 Decoder

组合逻辑电路，接收32位指令，输出一组控制信号，控制CPU的每一个部件的行为

opcode 决定"数据通路形态"（控制信号），funct3 + funct7 只在需要决定 ALU 具体运算时使用。这是 RISC-V 的三级分类系统：

- `opcode[6:0]`：一级分类——数据通路怎么走？
- `funct3[14:12]`：二级分类——同一大类下的子类型
- `funct7[31:25]`：三级分类——funct3 不够用时的额外区分

采用Main Decoder和ALU Decoder两层设计，更清晰一些，实际综合电路不变

## 8/13 2×2 Systolic Array

4个PE按网格连线：a向右传，b向下传，psum留在PE内（Output Stationary）

每个PE的寄存器导致1拍延迟，因此输入必须**偏斜（skew）**：b01比b00晚1拍、a10比a00晚1拍，数据才能在阵列内自动对齐

```
         a_in[0]   a_in[1]   b_in[0]   b_in[1]
沿 T0:   a00       x         b00       x
沿 T1:   a01       a10       b10       b01
沿 T2:   x         a11       x         b11
沿 T3:   （内部流水自动排空）
```

2×2×2矩阵乘耗时4拍（8次MAC，平均2 MAC/拍），各PE完成时刻不统一：c00在T1完成，c11要等到T3

### 阵列尺寸 vs 矩阵尺寸

- K维（内积维）：任意长度，直接多喂数据即可，限制是累加器位宽
- M/N维（输出维）：超出2×2需**分块（tiling）**，块间用clear分隔、结果外部累加——TPU也是这么做的
- 大阵列的价值：分块次数少，fill/drain开销占比低，利用率高

### 脉动阵列 vs CPU

**关键纠正**：单周期CPU是每周期1条**指令**，不是1次MAC。一次MAC ≈ 5条指令（2×lw + mul + add + sw），且RV32I无乘法指令需软件模拟

| | 2×2阵列 | 单周期CPU（无乘法） |
|---|---|---|
| 8次MAC耗时 | 4拍 | ~800+拍 |

阵列的根本优势：**并行**（多PE同时算）+ **数据重用**（每个元素读入一次、被多个PE使用，减少内存带宽压力）

## 8/20 Accelerator Top (Memory-Mapped 接口)

把脉动阵列封装成"内存"，CPU 用普通 sw/lw 控制它——**软件硬件之间的契约就是地址映射表**：

```
0x300-0x31C: A00..B11（可读可写）
0x320: 写→start 触发（wdata[0]）；读→STATUS（bit0=done）——同一地址读写语义不同
0x324-0x330: C00..C11（只读，66位 psum 截断到低32位）
```

### 结构三层

1. **寄存器组**：8个A/B寄存器，`mem_write && addr命中` 时写入
2. **控制FSM**：IDLE→FEED0→FEED1→FEED2→FEED3→DONE→IDLE，把 skewing 时刻表"演"出来喂给阵列；start = mem_write && addr==0x320 && wdata[0]（总线上的**一拍脉冲**，非寄存器）
3. **结果快照**：done=1 的那个沿把 live psum 锁进 snap 寄存器——CPU 之后**任何时候**读都是正确结果

### 关键设计决策：为什么需要快照

FSM 在 DONE 状态拉 clear=1（为下一轮清零）。但单周期 CPU 看到 done=1 后**下一拍**才能读结果——而 clear 恰好在这中间把 psum 抹掉了。**clear 的位置是协议设计问题**：必须发生在"结果被读走之后"。

快照方案解决：DONE 沿同时完成"快照保存 + 清零累加器"，两者用 NBA 语义天然无竞争（快照读沿前旧值，清零写沿后新值）。依赖：done 只拉高一拍（因为 DONE 的次态无条件离开）——若改成 DONE 等待新 start，快照会被后续清零周期摧毁，需要改成边沿检测。

### TB 教训：零时间读写竞争

改变组合逻辑输入后，**同一个仿真时刻**立刻读其输出 = race：仿真器用 delta cycle 传播组合逻辑，读到的是旧值。TB 里检查组合值必须放在时间控制（`@(posedge clk)` / `#1`）之后。

真实 CPU 天然没有这个问题：周期开始设地址、周期末锁存数据，组合逻辑有整拍稳定时间。

### iverilog 三个坑（均为工具限制，非设计错误）

- enum + 三元运算符 → 需要显式 cast，改用 localparam
- unpacked 数组元素接模块输出端口后不能过程赋值 → 用独立命名信号
- always_comb 里常量部分选择 `[31:0]` 不支持 → 预提取成 wire

## 8/22 任意K扩展 + TB阻塞/非阻塞确定原则

### 任意K（内积维）与64位输出

- A/B 寄存器组 → K_MAX 定长缓冲，FSM 从硬编码 FEED0-3 → 单 FEED 状态 + 计数器 t（0..K+1），退出条件 `t==K+1`
- 通用 skewing 公式：直送输入 (t<K) 读缓冲前半段；偏斜输入 (1≤t≤K) 读后半段，**偏移基准是 K_MAX 不是运行时 K**（当天抓到的最隐蔽 RTL bug）
- 64 位输出：lo/hi 寄存器对——快照逻辑零改动，只是 rdata MUX 多接几根线

### TB 阻塞（=）与非阻塞（<=）的确定原则（本项目最重要的 TB 教训）

| 场景 | 用 | 原因 |
|---|---|---|
| DUT 时序逻辑（always_ff） | `<=` | 沿后统一更新，正确建模寄存器 |
| DUT 组合逻辑（always_comb） | `=` | 立即更新 |
| **TB 与时钟沿同步的总线激励** | **`<=`** | 见下 |
| TB 内部变量（timeout/errors） | `=` | 单进程内无竞争 |

- **竞争机制**：TB 在 `@(posedge)` 恢复后立刻用 `=` 改总线，与 DUT 的 always_ff 采样处于**同一 active region**——调度顺序决定 DUT 采到旧值还是新值，导致**写入随机丢失**（本次故障：失败位置随 TB 微小改动漂移，隔离测试查不到，写监视器才定位）
- **NBA 为何安全**：`<=` 的更新推迟到 NBA region，在所有 active region 进程（含 always_ff 的 RHS 求值）**之后**生效——与调度顺序无关
- **Verilator 的 INITIALDLY 警告是误报**：该规则针对"纯初始化 initial 块"（t=0 执行一次，`<=` 与 `=` 无区别）；时钟同步的 TB 驱动进程是规则未覆盖的例外
- **遗留隐患**：pe_tb / systolic_2x2_tb 用 `=` 驱动输入，目前调度碰巧有利而通过，修改后若出现神秘失败先查这里
