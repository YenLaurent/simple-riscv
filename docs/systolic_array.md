# Systolic Array: 2×2 Memory-Mapped Coprocessor

## 架构总览

```
CPU (RV32I 单周期)                         加速器 (accelerator_top)
  sw/lw ──→ 数据总线 ──→ ┌────────────────┬──────────────┐
                         │ A/B 缓冲        │ 计数 FSM     │
                         │ (K_MAX 定长)    │ IDLE→FEED×t  │
                         │ (memory-mapped) │ →DONE        │
                         └────────┬───────┴──────┬───────┘
                                  │ a_feed/b_feed │ clear
                                  ▼               ▼
                         ┌─────────────────────────────┐
                         │ systolic_2x2: 4 个 PE 网格   │
                         │ a 向右流，b 向下流           │
                         │ psum 留在 PE 内 (output-    │
                         │ stationary)                 │
                         └──────────────┬──────────────┘
                                        │ c00..c11 (70-bit)
                                        ▼
                                快照寄存器 → lo/hi 拆分 → CPU 读回 64 位
```

## PE（Processing Element）

- 每周期一次 MAC：`psum <= psum + a_in * b_in`
- 数据直通（打一拍）：`a_out <= a_in`，`b_out <= b_in`——打拍保证 a/b/psum 同步流动，临界路径不随阵列规模增长
- `clear` 清零累加器但**不阻断数据流**
- 位宽：DATA_WIDTH=32，ACC_WIDTH=70（64b 积 + 6b 累加余量，支持 K_MAX=16）
- Output-stationary：psum 留在 PE 内部，输出端口直接就是内部 psum 寄存器

## 2×2 阵列与输入偏斜（Skewing）

每个 PE 计算输出矩阵的一个元素：`c_ij = Σ_k a_ik · b_kj`。

PE 的 1 拍寄存器延迟导致数据到达不同 PE 的路径长度不同，输入必须故意错开。**通用 K 的 skewing 公式**（计数器 t 从 0 到 K+1，共 K+2 个馈入周期）：

```
a_feed[0] = (t <  K)           ? a_buf[t]          : 0    ← 前半段，不偏斜
b_feed[0] = (t <  K)           ? b_buf[t]          : 0
a_feed[1] = (1 <= t && t <= K) ? a_buf[K_MAX+t-1]  : 0    ← 后半段，偏斜 1 拍
b_feed[1] = (1 <= t && t <= K) ? b_buf[K_MAX+t-1]  : 0
```

- 缓冲布局（K_MAX 定长）：`a_buf[0..K_MAX-1]`=A 第 0 行，`a_buf[K_MAX..2K_MAX-1]`=A 第 1 行；b_buf 同构存放 B 的第 0/1 列
- **偏斜输入的偏移基准是 K_MAX，不是运行时 K**——这是本次扩展中抓到的最隐蔽 bug
- 2×K × K×2 矩阵乘耗时 **K+2 拍**；各 PE 完成时刻不统一（c00 最早，c11 最后）

## Memory-Mapped 接口（地址映射 = 软硬件契约）

| 地址          | 寄存器                    | 读写                      |
| ----------- | ---------------------- | ----------------------- |
| 0x300-0x33C | A 第 0 行（K_MAX=16 个槽位）  | 读写                      |
| 0x340-0x37C | A 第 1 行                | 读写                      |
| 0x380-0x3BC | B 第 0 列                | 读写                      |
| 0x3C0-0x3FC | B 第 1 列                | 读写                      |
| 0x400       | START / STATUS         | 写 bit0=1 触发；读 bit0=done |
| 0x404       | K 寄存器（1..K_MAX，复位默认 2） | 读写                      |
| 0x408/0x40C | C00 低 32 位 / 高 32 位    | 只读                      |
| 0x410/0x414 | C01 lo / hi            | 只读                      |
| 0x418/0x41C | C10 lo / hi            | 只读                      |
| 0x420/0x424 | C11 lo / hi            | 只读                      |

CPU 侧握手协议（硬件 FSM 自动完成 skewing）：

```
1. sw 写 A/B（2K+2K 个元素，按 K_MAX 定长偏移）
2. sw 0x404 = K（必须在 start 之前）
3. sw 0x400 = 1（触发 start，总线上一拍脉冲）
4. lw 轮询 0x400 直到 bit0=1（done）
5. lw 读回 8 个 lo/hi 寄存器
```

cpu_top 集成：地址译码 `acc_sel = (addr ∈ [0x300, 0x424])`，dmem 与加速器的读写使能**对称门控**（`mem_write && acc_sel` / `mem_write && !acc_sel`），读数据 MUX 二选一——LSU 无感知。

## 控制 FSM

```
IDLE ──start──→ FEED(t=0..K+1) ──→ DONE ──→ IDLE
```

- **计数器化**：FEED0-3 硬编码 → 单 FEED 状态 + 计数器 t；退出条件 `t == K+1`（排空拍不能提前走）
- IDLE 保持 clear=1：空闲时持续清零，免去专门的清零周期
- 三个关键设计：
  1. **done 是粘性标志**（done_flag 寄存器）：CPU 轮询循环每 2-3 拍才采样一次，1 拍窄脉冲有 ~50% 概率被错过导致死锁。标志置位后保持，直到下一次 start 复位
  2. **结果快照**：DONE 沿同时完成"快照保存 + clear 清零"，NBA 语义下无竞争（快照读沿前旧值，清零写沿后新值）。CPU 之后任何时刻读结果都正确
  3. **K 钳位**：`k <= min(wdata[4:0], K_MAX)`——防止越界读缓冲产生 X

| 测试 | 内容 | 结果 |
|---|---|---|
| K=2 回归 | 不写 K（复位默认值）[1 2; 3 4]×[5 6; 7 8] | 19/22/43/50 ✓ |

## 性能对比（K=8，mcycle 实测）

| | 加速器路径 | CPU 纯软件路径 |
|---|---|---|
| 总周期（含一次期望值计算的共同开销） | **4859**（10 轮） | **6220**（3 轮） |
| 每轮估计 | **~310 周期** | **~1490 周期** |
| 每轮中纯计算 | 阵列 K+4 = 12 拍 | 32 次软件乘法 ~1200 拍 |

- **端到端加速比：~4.8×**（K=2 时为 3.5×，规模外推得到验证）
- **纯计算加速比：~125×**
- 加速路径每轮 310 周期中约 130 周期是 CPU 写 34 个寄存器（每次 sw 附带 ~3 条地址计算指令）——**通信开销仍主导，但占比随 K 增长从 96% 降到 ~85%**

### 关键结论

2×2 尺度下加速器几乎不值得；K 增大时加速比稳步上升，逐步逼近搬运带宽决定的上限。真实系统（TPU）同理：数据搬运 O(N²) vs 计算 O(N³)，规模越大加速器越值得。

## 局限与扩展方向

- M/N 维超出 2×2 需分块（tiling），块间结果外部累加——TPU 的做法
- K 上限由 K_MAX（16）与累加器位宽（70 位）约束；更大 K 需加宽 ACC_WIDTH 与缓冲
- 65:64 位（累加余量位）在 lo/hi 拆分中被舍弃

## 工程教训：TB 激励竞争

调试中抓到的最有价值的 bug 不是 RTL 而是 TB：**用阻塞赋值在时钟沿更新总线激励，与 DUT 的 always_ff 采样处于同一 active region——调度顺序决定 DUT 采到旧值还是新值，写入随机丢失**。修复：与时钟沿同步的总线激励一律用非阻塞赋值 `<=`（NBA 更新在所有 active region 进程之后生效，与调度顺序无关）。详见学习笔记 8/22 条目。
