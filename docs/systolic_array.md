# Systolic Array: 2×2 Memory-Mapped Coprocessor

## 架构总览

```
CPU (RV32I 单周期)                         加速器 (accelerator_top)
  sw/lw ──→ 数据总线 ──→ ┌────────────────┬──────────────┐
                         │ 寄存器组       │ 控制 FSM     │
                         │ A00..B11       │ IDLE→FEED×4  │
                         │ (memory-mapped)│ →DONE        │
                         └────────┬───────┴──────┬───────┘
                                  │ a_feed/b_feed│ clear
                                  ▼              ▼
                         ┌─────────────────────────────┐
                         │ systolic_2x2: 4 个 PE 网格  │
                         │ a 向右流，b 向下流          │
                         │ psum 留在 PE 内 (output-    │
                         │ stationary)                 │
                         └──────────────┬──────────────┘
                                        │ c00..c11 (66-bit)
                                        ▼
                                快照寄存器 → 32 位截断 → CPU 读回
```

## PE（Processing Element）

- 每周期一次 MAC：`psum <= psum + a_in * b_in`
- 数据直通（打一拍）：`a_out <= a_in`，`b_out <= b_in` —— 打拍保证 a/b/psum 同步流动，临界路径不随阵列规模增长
- `clear` 清零累加器但**不阻断数据流**
- 位宽：DATA_WIDTH=32，ACC_WIDTH=66（64b 积 + 2b 累加余量）
- Output-stationary：psum 留在 PE 内部，无 psum_in/out 端口；输出端口直接就是内部 psum 寄存器

## 2×2 阵列与输入偏斜（Skewing）

每个 PE 计算输出矩阵的一个元素：`c_ij = Σ_k a_ik · b_kj`。

PE 的 1 拍寄存器延迟导致数据到达不同 PE 的路径长度不同，输入必须故意错开：

```
         a_in[0]   a_in[1]   b_in[0]   b_in[1]
沿 T0:   a00       x         b00       x
沿 T1:   a01       a10       b10       b01
沿 T2:   x         a11       x         b11
沿 T3:   （内部流水排空）
```

- 2×2×2 矩阵乘耗时 **4 拍**（8 次 MAC，平均 2 MAC/拍）
- 各 PE 完成时刻不统一：c00 在 T1 完成，c11 要等到 T3

## Memory-Mapped 接口

地址映射（软硬件契约）：

| 地址 | 寄存器 | 读写 |
|---|---|---|
| 0x300-0x31C | A00..A11, B00..B11 | 可读可写 |
| 0x320 | START / STATUS | 写 bit0=1 触发；读 bit0=done |
| 0x324-0x330 | C00..C11 | 只读（66 位 psum 截断到低 32 位） |

CPU 侧的握手协议（硬件 FSM 自动完成 skewing）：

```
1. sw 写 8 个 A/B 元素
2. sw 0x320 = 1（触发 start，总线上一拍脉冲）
3. lw 轮询 0x320 直到 bit0=1（done）
4. lw 读回 4 个结果
```

## 控制 FSM

```
IDLE ──start──→ FEED0 → FEED1 → FEED2 → FEED3 → DONE → IDLE
```

- IDLE 保持 clear=1：空闲时持续清零，免去专门的清零周期
- FEED0-3 把 skewing 时刻表"演"出来喂给阵列
- 两个关键设计：
  1. **done 是粘性标志**（done_flag 寄存器）：CPU 轮询循环每 2-3 拍才采样一次，1 拍的窄脉冲有 ~50% 概率被错过导致死锁。标志置位后保持，直到下一次 start 才复位
  2. **结果快照**：DONE 沿同时完成"快照保存 + clear 清零"。两者在同一 NBA 区域执行，快照读沿前旧值、清零写沿后新值，无竞争。CPU 之后任何时刻读结果都正确

## 测试结果

- accelerator_top TB：两轮矩阵乘 + 快照持久性 + 越界读，16 项检查全部通过
- 端到端（CPU 驱动）：`[1 2; 3 4] × [5 6; 7 8] = [19 22; 43 50]` ✓，自检码 0x600

## 性能对比（mcycle 实测）

| | 加速器路径 | CPU 纯软件路径 |
|---|---|---|
| 单次 2×2 矩阵乘 | **111.2 周期**（10 轮，mcycle=1112） | **391 周期**（3 轮，mcycle=1173） |
| 其中纯计算 | 阵列 5 拍 | 软件乘法 ~250 拍（RV32I 无 mul 指令，移位-加法模拟） |
| 其余 | 数据搬运 8sw+4lw+轮询+自检 ~106 拍 | 循环/寻址/自检 ~141 拍 |

- **端到端加速比：3.5×**
- **纯计算加速比：~50×**

### 关键结论：通信开销主导

2×2 尺度下，加速器路径 111 拍中阵列计算只占 5 拍（4.5%），其余全部是 CPU 侧数据搬运。50× 与 3.5× 之间的差距就是通信开销——这正是加速器设计的核心权衡（Amdahl 定律：串行的搬运部分无法被并行阵列加速）。

### 规模外推

K（内积维）增大时：CPU 路径随 K 线性增长（8K 次 MAC × ~20 条指令），加速器路径的阵列时间仅 K+2 拍、搬运随 K 线性但常数小——加速比随 K 增长，逐步逼近搬运带宽决定的上限。真实系统（TPU）同理：数据搬运 O(N²) vs 计算 O(N³)，规模越大加速器越值得。

## 局限与扩展方向

- 阵列硬编码 2×2、K=2；扩展方向：K 参数化（FSM 计数器化 + A/B 缓冲改为存储器）
- M/N 维超出 2×2 需分块（tiling），块间结果外部累加——TPU 的做法
- 结果截断到 32 位（真实设计应提供 lo/hi 两个寄存器）
